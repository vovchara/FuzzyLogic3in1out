# Прошивка стенда (ESP32, ESP-NOW)

Дві програми для Arduino IDE:

- `node/` — мобільний вузол: міряє напругу спарки через дільник на D34 і
  раз на 200 мс шле ESP-NOW-пакет TELEMETRY (`node_id`, `seq`, напруга,
  `t_tx` + таблиця сусідів, яких він чує). Відповідає на ехо-пінги БС.
  Працює автономно від батареї; на кожну відправку блимає бортовий LED.
- `base/` — базова станція («радіомодем»): приймає пакет, дописує RSSI і
  час прийому, друкує CSV у Serial на 115200 і по колу пінгує відомі
  вузли. Формати рядків і заголовки — РІВНО константи `TELEMETRY_HEADER`,
  `NEIGHBOR_HEADER`, `RTT_HEADER` з `src/simulation/telemetry.ts` (єдине
  джерело правди; парсер апки пропускає повторні заголовки після
  ресетів БС).
  Два зовнішні модулі світлодіодів 10 мм показують канал наживо:
  **зелений на D25** блимає на кожен прийнятий пакет, **червоний на
  D22** світиться 0,3 с, коли в `seq` якогось вузла пропуск (пакет
  загубився в ефірі). Ресет вузла (seq пішов з початку) втратою не
  вважається. Модулі живляться від 3V3.

## Збірка і прошивання

1. Arduino IDE з ядром **arduino-esp32 3.x** (менеджер плат → esp32 by
   Espressif Systems); плата **ESP32 Dev Module**, **Flash Mode → DIO**,
   порт — CP2102 (`/dev/cu.usbserial-…` на macOS). З arduino-cli:
   `--fqbn esp32:esp32:esp32:FlashMode=dio`.

   ⚠️ DIO обовʼязковий: на частині плат стоїть флеш GigaDevice, який не
   вмикає QIO (дефолт для Dev Module) — прошивка тоді вічно ребутиться
   з `qio_mode: Failed to set QIE bit` → `assert failed:
   __esp_system_init_fn_init_flash`. DIO працює на всіх платах, а
   швидкість флеша цим скетчам байдужа.
2. Для кожного мобільного вузла свій `NODE_ID` (плата №1 = вузол №1 у
   розстановці). У репо `node.ino` лишається з `NODE_ID 1`: для вузла N
   робиться копія скетча поза репо і шиється вона:
   ```sh
   mkdir -p /tmp/node3/node && sed 's/^#define NODE_ID 1$/#define NODE_ID 3/' \
     node/node.ino > /tmp/node3/node/node.ino
   arduino-cli compile --upload -p /dev/cu.usbserial-0001 \
     --fqbn esp32:esp32:esp32:FlashMode=dio /tmp/node3/node
   ```
   Протокол v2 ефірно несумісний з v1: БС і всі вузли перепрошиваються
   разом.
3. Базова станція прошивається як є і працює голою від USB ноутбука —
   макетка і дільник їй не потрібні.

⚠️ **Живлення спарки — тільки у VIN** (8,4 В у USB спалить плату).
На час прошивання по USB спарку від VIN відʼєднати.

## Калібрування дільника

Дільник 3×7,5 кОм ділить напругу на 3 (константа `DIVIDER_RATIO` у
`node.ino`). Після збирання:

1. Заміряти напругу спарки мультиметром.
2. Підключити вузол по USB, відкрити Serial Monitor (115200) — вузол
   друкує відправлену напругу (`voltage=…`).
3. Якщо розходиться — підправити `DIVIDER_RATIO`
   (нове = старе × виміряне/надруковане) і перепрошити.

## Захоплення CSV (macOS)

```sh
ls /dev/cu.usbserial-*
stty -f /dev/cu.usbserial-XXXX 115200
cat /dev/cu.usbserial-XXXX > capture.csv
```

Зупинити — Ctrl+C. Для вимірювальних сесій зручніше
`private/tools/capture.sh` (відкриває порт до ресету сам, пише QC-звіт).

⚠️ **Порядок важливий: спочатку запустити `cat`, ПОТІМ натиснути EN
на базовій станції.** CP2102 на цих платах глючить, якщо порт
відкривається посеред передачі: починає зациклено повторювати вже
передані байти (у рази швидше за фізичні 115200 бод) і одужує лише з
приходом нових даних. Старт захоплення з ресету БС дає чистий потік;
кілька службових рядків завантажувача на початку — норма, парсер
покаже їх як помилки рядків і проігнорує, а заголовок надрукується
після них. Далі `capture.csv` разом із файлом розстановки → вкладка
«Експеримент» (кнопки «Розстановка…» і «Захоплення…»). При періоді
200 мс серія 50–100 пакетів на точку — це 10–20 с захоплення; для
розстановки краще 60 с, щоб набралось кілька десятків пінгів на вузол.

## Формат CSV (протокол v2)

БС на старті друкує три заголовки, далі рядки трьох видів:

```
node_id,seq,voltage,rssi,t_tx_ms,t_rx_ms
nb,reporter_id,reporter_seq,neighbor_id,heard,first_seq,last_seq,rssi_sum,rssi_sq_sum
rtt,node_id,ping_seq,rtt_us
3,1500,7.25,-75,301234,1234567
nb,3,1500,1,1480,3,1500,-111000,8300000
rtt,3,61,4120
```

- **Основний рядок** — формат v1 без змін, тож старі захоплення
  парсяться як раніше (лише без лінків і RTT).
- **`nb`** — після кожного основного рядка, по одному на сусіда зі звіту
  цього пакета: `reporter` чує `neighbor`. Усі лічильники
  накопичувальні з моменту старту репортера, тож загублений звіт нічого
  не ламає: PDR лінка = Δheard / Δlast_seq між першим і останнім звітом
  у захопленні, середній RSSI і σ — з Δrssi_sum і Δrssi_sq_sum. Ребут
  репортера (падає `reporter_seq`) чи сусіда (падає `last_seq`)
  розбиває ряд на сегменти, Δ сумуються — ребут не рахується втратою.
  Сусід був в ефірі, а репортер про нього мовчить — виміряний PDR 0.
- **`rtt`** — на кожен понг; загублений пінг просто не має рядка, втрати
  парсер рахує за дірками в `ping_seq` (нумерація своя для кожного
  вузла, після ребуту БС іде з початку). TD = медіана `rtt_us` / 2.
- Рядки `nb`/`rtt` починаються з літерного тегу — їх не сплутати з
  числовими. Повтори рядків від глюку CP2102 відкидаються як точні
  дублікати.

**Навантаження Serial.** 115200 бод ≈ 11,5 КБ/с. На 5 вузлах:
25 пакетів/с × (основний рядок ≈ 31 Б + 4 рядки `nb` по ≈ 41–48 Б) +
4 рядки `rtt`/с по ≈ 18 Б ≈ 5–5,6 КБ/с, тобто ≈ 45–50 % каналу (числа
довшають з часом роботи, звідси діапазон). Запас є; черга прийому (32)
не росте, бо рядки `nb` розгортаються в `loop()` з одного запису.
Перевіряється на столі: немає дірок у `seq` при всіх вузлах поруч.

## Файл розстановки

Пара до захоплення для вкладки «Експеримент» і
`capture.sh --layout` — JSON, метри, початок координат знизу зліва:

```json
{
  "name": "Паркінг, розстановка А",
  "date": "2026-10-24",
  "field": 100,
  "base": { "x": 0, "y": 0 },
  "orientation": "лицем до БС",
  "nodes": [
    { "id": 1, "x": 10, "y": 5, "dat": 10 },
    { "id": 2, "x": 25, "y": 30 }
  ],
  "notes": ""
}
```

`field` — сторона квадрата (дефолт 100), усі координати в `[0, field]`;
`dat` необов'язковий (дефолт — значення за замовчуванням змінної Dat
контролера агрегації); `orientation`/`notes` — вільний текст для
методики. Апка перевіряє файл і показує помилки по полях.

## Протокольні рішення

- **Типи пакетів.** Після magic іде байт типу: `TELEMETRY` (1),
  `PING` (2), `PONG` (3). Таблиця сусідів — до `MAX_NEIGHBORS = 8`
  записів по 21 байту, шлються лише вже почуті: повний пакет 183 байти
  при ліміті ESP-NOW 250.
- **Телеметрія — broadcast, не unicast.** Вузли шлють на
  FF:FF:FF:FF:FF:FF: не треба зашивати MAC базової станції (будь-яку
  плату можна перепрошити в БС), а без MAC-ретраїв втрачений пакет
  лишається втраченим — PDR у логу відбиває реальний канал, а не бюджет
  повторів. Той самий broadcast чують інші вузли — з нього їхні
  таблиці сусідів.
- **Ехо-пінг — unicast, з повторами.** БС запам'ятовує MAC кожного
  вузла з його телеметрії й раз на 250 мс пінгує наступного по колу;
  вузол відповідає з `loop()` (не з callback). Unicast отримує
  MAC-повтори ESP-NOW — і це задум: на поганому лінку RTT росте за
  рахунок повторів, і це та сама затримка, яку модель `delayMs` рахує з
  PDR. RTT міряється одним годинником БС (`micros()` у пінгу, луна в
  понгу), тож синхронізація годинників не потрібна.
- **Канал WiFi фіксований** (`ESPNOW_CHANNEL = 1`) в обох прошивках —
  ESP-NOW вимагає спільного каналу.
- **Магічне число** `0xF37A` у пакеті відсіює чужий ESP-NOW-трафік.
- **Годинники не синхронізуються.** `t_tx_ms`/`t_rx_ms` — це millis()
  двох різних плат; різниця не є затримкою. Парсер їх валідує, але не
  споживає; затримку дає ехо-пінг.
- Структура пакета продубльована в обох скетчах (Arduino IDE не бачить
  заголовків поза текою скетча) — правити синхронно, блоки позначені.
